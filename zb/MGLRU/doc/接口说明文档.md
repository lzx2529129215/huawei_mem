# cache_ext + MGLRU debugfs 接口说明

本文档对应当前实验补丁逻辑：

- 最终补丁：`merged_cache_ext.patch`
- 该补丁已合并 reclaim skip 统计修复和 `predicted_op` 的 active hint 统计更新

主补丁新增两个 debugfs 接口：

```text
/sys/kernel/debug/cache_ext
/sys/kernel/debug/lru_gen_pages
```

其中：

- `cache_ext` 是应用预测页缓存保护接口，按文件页 profile 匹配 folio。
- `lru_gen_pages` 是 PFN 级 MGLRU 手工调试接口，用于 promote/protect/scan skip/scan only。

## 1. 启动与检查

确认正在运行实验内核：

```bash
uname -r
```

示例：

```text
6.17.0-cacheext-v2
```

确认 debugfs 已挂载：

```bash
mount | grep debugfs || sudo mount -t debugfs debugfs /sys/kernel/debug
```

确认接口存在：

```bash
sudo ls -l /sys/kernel/debug/cache_ext
sudo ls -l /sys/kernel/debug/lru_gen_pages
```

读取状态：

```bash
sudo cat /sys/kernel/debug/cache_ext
sudo cat /sys/kernel/debug/lru_gen_pages
```

## 2. cache_ext 总体语义

`cache_ext` 保护的是符合 profile 的文件页 folio。

一次 reclaim scan 批次开始时：

```text
isolate_folios()
  -> cache_ext_begin_reclaim_cycle(sc)
```

后续 folio 扫描阶段：

```text
isolate_folio()
  -> cache_ext_can_isolate(folio)
```

返回语义：

```text
cache_ext_can_isolate(folio) == true
    允许原 MGLRU 逻辑继续 isolate/reclaim

cache_ext_can_isolate(folio) == false
    folio 命中 cache_ext profile，跳过本次 reclaim isolation
```

重要点：

- `cache_ext` 不替换 MGLRU generation 算法。
- `cache_ext` 只在命中 profile 时阻止 reclaim isolation。
- 匿名页、swapbacked folio、没有 mapping 的 folio、没有 inode 的 folio 都不会被 cache_ext 保护。
- `cache_ext_begin_reclaim_cycle()` 只负责 BPF policy 模式下的周期预测；builtin/manual 模式不依赖它刷新预测值。

## 3. cache_ext 匹配条件

profile 写入格式：

```text
profile add <app_id> <op_id> <dev_major> <dev_minor> <ino> <index_start> <index_end> <priority>
```

folio 只有同时满足以下条件才算命中：

```text
cache_ext enabled == 1
current_predicted_next_op != 0
folio 不是 swapbacked
folio_mapping(folio) != NULL
mapping->host != NULL
inode->i_sb != NULL
profile.app_id == cache_ext_state.app_id
profile.op_id == cache_ext_state.predicted_next_op
profile.dev_major == MAJOR(inode->i_sb->s_dev)
profile.dev_minor == MINOR(inode->i_sb->s_dev)
profile.ino == inode->i_ino
folio index 范围与 profile index 范围重叠
```

内核侧使用字段：

```c
mapping = folio_mapping(folio);
inode = mapping->host;
dev = inode->i_sb->s_dev;
dev_major = MAJOR(dev);
dev_minor = MINOR(dev);
ino = inode->i_ino;
index_start = folio->index;
index_end = folio->index + folio_nr_pages(folio) - 1;
```

用户态推荐用同一个目标文件计算 profile：

```python
import os

st = os.stat(path)
dev_major = os.major(st.st_dev)
dev_minor = os.minor(st.st_dev)
ino = st.st_ino
page_size = os.sysconf("SC_PAGE_SIZE")
index_start = 0
index_end = (st.st_size + page_size - 1) // page_size - 1
```

注意：

- 不要硬写 4096；应使用系统 page size。
- `index_end` 建议向上取整，避免文件大小不是 page size 整数倍时漏掉最后一页。
- `priority` 当前只记录在 profile 中，匹配路径暂未使用它做过滤。

## 4. cache_ext 命令

所有写入命令建议使用：

```bash
echo "<command>" | sudo tee /sys/kernel/debug/cache_ext
```

### 4.1 enable

```text
enable 0
enable 1
```

作用：

- `enable 1` 开启 cache_ext 保护逻辑。
- `enable 0` 关闭 cache_ext 保护逻辑。

示例：

```bash
echo "enable 1" | sudo tee /sys/kernel/debug/cache_ext
```

### 4.2 app

```text
app <app_id>
```

设置当前 app id。

示例：

```bash
echo "app 4" | sudo tee /sys/kernel/debug/cache_ext
```

### 4.3 policy

```text
policy builtin
policy bpf
```

作用：

- `policy builtin`：使用 debugfs 手动设置的 `predicted_op`。
- `policy bpf`：在 reclaim cycle 开始时调用 BPF predict hook 更新预测 op。

如果内核未启用 `CONFIG_CACHE_EXT_BPF`，写入 `policy bpf` 会返回 `-EOPNOTSUPP`。

### 4.4 bpf enable

```text
bpf enable 0
bpf enable 1
```

只在 `CONFIG_CACHE_EXT_BPF=y` 时有效。

`policy bpf` 且 `bpf enable 1` 时，`cache_ext_begin_reclaim_cycle()` 会在 `isolate_folios()` 开始处调用：

```c
cache_ext_bpf_predict(&ctx)
```

返回值含义：

- `ret > 0 && ret <= USHRT_MAX`：作为新的 `current_predicted_next_op`。
- `ret <= 0`：清空 `current_predicted_next_op`，本轮不保护任何 profile。

### 4.5 predicted_op

```text
predicted_op <app_id> <op_id>
```

手动设置当前预测操作。builtin/manual 模式下，这是最直接的驱动方式。

示例：

```bash
echo "predicted_op 4 22" | sudo tee /sys/kernel/debug/cache_ext
```

当前匹配路径直接使用：

```text
cache_ext_state.app_id
cache_ext_state.predicted_next_op
```

因此 `bpf_enabled=0` 时，manual `predicted_op` 仍然可以驱动 profile 匹配。

在 `merged_cache_ext.patch` 中，写入 `predicted_op` 会同时增加：

```text
predicted_updates
active_hint_updates
```

如果运行内核中 `active_hint_updates` 在 builtin/manual 模式下一直为 0，说明仍在使用旧统计逻辑，但这不影响 profile 匹配。

### 4.6 profile add

```text
profile add <app_id> <op_id> <dev_major> <dev_minor> <ino> <index_start> <index_end> <priority>
```

示例：

```bash
echo "profile add 4 22 8 3 5123183 0 129940 1" | sudo tee /sys/kernel/debug/cache_ext
```

含义：

- `app_id`：应用 id。
- `op_id`：操作 id，必须与当前 `predicted_op` 的 op 匹配才生效。
- `dev_major/dev_minor`：来自 `os.stat(path).st_dev`。
- `ino`：来自 `os.stat(path).st_ino`。
- `index_start/index_end`：文件页 page index 范围。
- `priority`：当前记录但不参与匹配。

当前实现最多保存：

```text
8192 profiles
```

如果 profile 表满，写入返回 `-ENOSPC`。

### 4.7 profile clear

```text
profile clear
```

清空所有 profile，但不清空当前 app/op 和统计计数。

### 4.8 clear

```text
clear
```

清空当前状态：

- `app_id = 0`
- `current_predicted_next_op = 0`
- `cycle_seq = 0`
- `policy_mode = builtin`
- `bpf_enabled = false`
- 清空统计计数

注意：当前实现的 `clear` 不调用 `cache_ext_clear_profiles_locked()`，因此不会清空 profile 表。需要清空 profile 时请单独执行：

```bash
echo "profile clear" | sudo tee /sys/kernel/debug/cache_ext
```

## 5. cache_ext 输出字段

读取：

```bash
sudo cat /sys/kernel/debug/cache_ext
```

示例：

```text
cache_ext enabled: 1
app_id: 4
policy_mode: builtin
bpf_supported: 1
bpf_enabled: 0
cycle_seq: 0
current_predicted_next_op: 22

profiles:
[0] app=4 op=22 dev=8:3 ino=5123183 index=0-129940 priority=1

stats:
predicted_updates: 1
cycle_refreshes: 0
active_hint_updates: 1
profile_hits: 12285
protected_folios: 12285
skipped_reclaim: 12285
aging_calls: 246
aging_hits: 0
aging_promoted: 0

bpf:
bpf_predict_calls: 0
bpf_predict_hits: 0
bpf_predict_miss: 0
bpf_predict_errors: 0
```

### 5.1 状态字段

- `cache_ext enabled`：总开关。
- `app_id`：当前用于匹配的 app id。
- `policy_mode`：`builtin` 或 `bpf`。
- `bpf_supported`：内核是否编译 `CONFIG_CACHE_EXT_BPF`。
- `bpf_enabled`：BPF predict 开关。
- `cycle_seq`：BPF policy reclaim cycle 序号。
- `current_predicted_next_op`：当前预测 op。

### 5.2 profile 字段

```text
[slot] app=<app_id> op=<op_id> dev=<major>:<minor> ino=<ino> index=<start>-<end> priority=<priority>
```

只有 `valid=true` 的 profile 会显示。

### 5.3 stats 字段

- `predicted_updates`：`predicted_op` 写入或 BPF predict 成功更新 op 的次数。
- `cycle_refreshes`：BPF policy 模式下进入 reclaim cycle 并调用 BPF predict 的次数。
- `active_hint_updates`：当前 active hint 更新次数。manual `predicted_op` 和 BPF predict 成功都会增加该计数。
- `profile_hits`：profile 命中次数。
- `protected_folios`：profile 命中并尝试保护 folio 的次数。
- `skipped_reclaim`：在 reclaim isolate 路径中，因为 profile 命中而跳过 reclaim 的次数。
- `aging_calls`：MGLRU aging/look-around 路径调用 `cache_ext_aging_should_promote()` 的次数。
- `aging_hits`：aging/look-around 路径 profile 命中次数。
- `aging_promoted`：aging/look-around 路径命中后执行 promote 的次数。

计数说明：

- `merged_cache_ext.patch` 中，`cache_ext_can_isolate()` 调用 `cache_ext_match_folio(folio, true)`。
- reclaim skip 命中会同步增加 `profile_hits/protected_folios/skipped_reclaim`。
- `aging_calls` 增加但 `aging_hits=0` 说明 aging 路径被调用，但这些 folio 没有命中当前 profile。

## 6. 推荐 cache_ext 实验流程

假设目标文件为 `$path`，应用 id 为 `4`，操作 id 为 `22`。

### 6.1 计算 profile 参数

```bash
python3 - <<'PY'
import os

path = "/path/to/target/file"
st = os.stat(path)
page_size = os.sysconf("SC_PAGE_SIZE")
print("dev_major", os.major(st.st_dev))
print("dev_minor", os.minor(st.st_dev))
print("ino", st.st_ino)
print("index_start", 0)
print("index_end", (st.st_size + page_size - 1) // page_size - 1)
print("page_size", page_size)
PY
```

### 6.2 初始化 cache_ext

```bash
echo "profile clear" | sudo tee /sys/kernel/debug/cache_ext
echo "clear" | sudo tee /sys/kernel/debug/cache_ext
echo "enable 1" | sudo tee /sys/kernel/debug/cache_ext
echo "policy builtin" | sudo tee /sys/kernel/debug/cache_ext
echo "predicted_op 4 22" | sudo tee /sys/kernel/debug/cache_ext
```

### 6.3 写入 profile

```bash
echo "profile add 4 22 8 3 5123183 0 129940 1" | sudo tee /sys/kernel/debug/cache_ext
```

### 6.4 检查状态

```bash
sudo cat /sys/kernel/debug/cache_ext
```

应看到：

```text
cache_ext enabled: 1
policy_mode: builtin
current_predicted_next_op: 22
[0] app=4 op=22 dev=8:3 ino=5123183 index=0-129940 priority=1
```

### 6.5 触发压力并观察

压测后再次读取：

```bash
sudo cat /sys/kernel/debug/cache_ext
```

如果命中 reclaim isolate 保护，通常应看到：

```text
profile_hits 增加
protected_folios 增加
skipped_reclaim 增加
```

如果只看到：

```text
skipped_reclaim 增加
profile_hits = 0
protected_folios = 0
```

说明运行内核很可能不是 `merged_cache_ext.patch` 对应版本，或仍在使用旧统计逻辑。

## 7. lru_gen_pages 总体语义

`lru_gen_pages` 是 PFN 级 MGLRU 调试接口。读取接口会显示支持的命令：

```text
# commands:
#   promote <pfn> <nr_pages>
#   protect add|del <pfn> <nr_pages>
#   scan skip add|del <prio_min> <prio_max> <pfn> <nr_pages>
#   scan only add|del <prio_min> <prio_max> <pfn> <nr_pages>
#   clear all
# pfn flags skip_prio_min skip_prio_max only_prio_min only_prio_max hits
```

当前代码不支持：

```text
query
depromote
```

不要按旧文档使用这两个命令。

## 8. lru_gen_pages 命令

### 8.1 promote

```text
promote <pfn> <nr_pages>
```

作用：

- 将指定 PFN 范围对应的 folio 移到当前 lruvec 最新 generation。
- 一次性操作，不写入持久策略表。

示例：

```bash
echo "promote 2150528 1" | sudo tee /sys/kernel/debug/lru_gen_pages
```

### 8.2 protect

```text
protect add <pfn> <nr_pages>
protect del <pfn> <nr_pages>
```

作用：

- `protect add`：把目标 folio 加入 PFN 保护表。
- `protect del`：删除目标 folio 的保护策略。

命中时：

- 在 reclaim sort 路径中调用 `mglru_page_policy_reheat()`。
- 将 folio promote 到最新 generation。
- 在 isolate 路径中调用 `mglru_page_policy_can_isolate()`，阻止 folio 被 isolate。
- 对应策略行 `hits` 增加。

示例：

```bash
echo "protect add 2150528 1" | sudo tee /sys/kernel/debug/lru_gen_pages
sudo cat /sys/kernel/debug/lru_gen_pages
```

### 8.3 scan skip

```text
scan skip add <prio_min> <prio_max> <pfn> <nr_pages>
scan skip del <prio_min> <prio_max> <pfn> <nr_pages>
```

作用：

- 当 `scan_control.priority` 落在 `[prio_min, prio_max]` 时，跳过目标 folio。
- 命中时也会 reheat 到最新 generation。

示例：

```bash
echo "scan skip add 0 12 2150528 1" | sudo tee /sys/kernel/debug/lru_gen_pages
```

### 8.4 scan only

```text
scan only add <prio_min> <prio_max> <pfn> <nr_pages>
scan only del <prio_min> <prio_max> <pfn> <nr_pages>
```

作用：

- 当任意 `only` 策略在当前 priority 生效时，只允许命中 `only` 集合的 folio 继续进入 isolate。
- 未命中 only 集合的 folio 会被跳过。

风险：

- `scan only` 影响面比 `protect` 和 `scan skip` 更大。
- only 集合太小时，可能显著改变系统 reclaim 行为。

### 8.5 clear all

```text
clear all
```

作用：

- 清空所有 `lru_gen_pages` PFN 策略。
- 不回滚已经执行过的 `promote`。

示例：

```bash
echo "clear all" | sudo tee /sys/kernel/debug/lru_gen_pages
```

## 9. lru_gen_pages 参数说明

### 9.1 pfn

`pfn` 是物理页帧号。

支持十进制：

```text
2150528
```

支持带 `0x` 前缀的十六进制：

```text
0x20d080
```

不要使用裸十六进制：

```text
20d080
```

原因是内核使用：

```c
kstrtoul(str, 0, value)
```

### 9.2 nr_pages

`nr_pages` 是从 `pfn` 开始覆盖多少个 base pages。

如果目标 PFN 属于 large folio，接口会归一化到 folio head PFN。

### 9.3 prio_min / prio_max

表示 `scan_control.priority` 闭区间：

```text
0 <= prio_min <= prio_max <= DEF_PRIORITY
```

常用范围：

```text
0 12
```

## 10. lru_gen_pages 输出字段

策略行格式：

```text
pfn flags skip_prio_min skip_prio_max only_prio_min only_prio_max hits
```

示例：

```text
2150528 PS- 0 12 0 12 3
```

字段说明：

- `pfn`：策略记录的 folio head PFN。
- `flags`：三位字符。
- `P`：protect 生效。
- `S`：scan skip 生效。
- `O`：scan only 生效。
- `-`：对应策略未设置。
- `skip_prio_min/skip_prio_max`：skip priority 范围。
- `only_prio_min/only_prio_max`：only priority 范围。
- `hits`：策略命中次数。

注意：

- 如果 flags 中没有 `S`，即使 skip priority 字段有默认值，skip 也不生效。
- 如果 flags 中没有 `O`，即使 only priority 字段有默认值，only 也不生效。

## 11. 常见现象解释

### 11.1 cycle_refreshes 一直是 0

在 builtin/manual 模式下正常。

`cycle_refreshes` 只在以下条件同时满足时增加：

```text
CONFIG_CACHE_EXT_BPF=y
cache_ext enabled == 1
policy_mode == bpf
bpf_enabled == 1
app_id != 0
进入 isolate_folios()
```

manual `predicted_op` 不依赖 `cycle_refreshes`。

### 11.2 active_hint_updates 一直是 0

如果运行内核仍是旧统计逻辑，builtin/manual 模式下可能一直为 0。

这是统计口径问题，不代表 `predicted_op` 没有生效。

在 `merged_cache_ext.patch` 中，写入 `predicted_op` 会让它增加。

### 11.3 skipped_reclaim 增加但 profile_hits 为 0

在 `merged_cache_ext.patch` 中，该路径应为：

```c
cache_ext_can_isolate()
  -> cache_ext_match_folio(folio, true)
```

如果运行时仍出现 `skipped_reclaim` 增加但 `profile_hits/protected_folios` 不增加，说明正在运行的内核不是最终补丁对应版本，或没有启动到新安装内核。

在 `merged_cache_ext.patch` 中，reclaim skip 命中应同步增加：

```text
profile_hits
protected_folios
skipped_reclaim
```

### 11.4 aging_calls 增加但 aging_hits 为 0

说明 MGLRU look-around aging 路径调用了 cache_ext，但当前 folio 没有命中 profile。

常见原因：

- 当前 aging 扫到的不是目标文件页。
- `app_id/op_id` 不匹配。
- `dev/ino/index` 不匹配。
- 文件没有足够 reclaim/aging 参与度。

### 11.5 profile 写入了但完全没有命中

优先检查：

```bash
sudo cat /sys/kernel/debug/cache_ext
```

确认：

- `cache_ext enabled: 1`
- `current_predicted_next_op` 非 0
- profile 的 `app/op` 与当前 `app_id/current_predicted_next_op` 一致
- profile 的 `dev/ino/index` 与目标文件一致
- 目标文件页确实进入 page cache 并参与 reclaim

## 12. 编译、安装与验证流程

本节整理当前 `6.17.0-cacheext-v2` 实验内核的有效编译测试流程。路径可按自己的环境调整。

### 12.1 目录与变量

推荐先设置环境变量：

```bash
cd ~/myOsTest

SRC=$PWD/linux-hwe-6.17-6.17.0
BUILD=$PWD/linux-hwe-6.17-cacheext-v2-build
MGLRU=$PWD/huawei_mem-master/zb/MGLRU
PATCH=$MGLRU/merged_cache_ext.patch
```

核心文件：

```text
$SRC/mm/cache_ext.c
$SRC/mm/vmscan.c
$SRC/include/linux/cache_ext.h
$MGLRU/ebpf/cache_ext_policy.bpf.c
$MGLRU/ebpf/cache_ext_bpf_common.h
$MGLRU/ebpf/cache_ext_loader.py
$MGLRU/generated/cache_ext_markov_transition.csv
$MGLRU/generated/cache_ext_page_profile.csv
```

### 12.2 应用补丁

先 dry-run：

```bash
patch -d "$SRC" -p1 --dry-run < "$PATCH"
echo $?
```

成功标准：

```text
0
```

正式应用：

```bash
patch -d "$SRC" -p1 < "$PATCH"
```

检查 `cache_ext_begin_reclaim_cycle(sc)` 是否在正确位置：

```bash
grep -n "static int isolate_folios" "$SRC/mm/vmscan.c"
sed -n '5254,5276p' "$SRC/mm/vmscan.c"
```

正确结构：

```c
static int isolate_folios(... struct scan_control *sc ...)
{
	int i;
	int type = get_type_to_scan(lruvec, swappiness);

#ifdef CONFIG_CACHE_EXT
	cache_ext_begin_reclaim_cycle(sc);
#endif

	for_each_evictable_type(i, swappiness) {
		...
	}
}
```

不要把 `cache_ext_begin_reclaim_cycle(sc)` 放进：

- `get_tier_idx()`
- `isolate_folio()`
- folio 循环内部

### 12.3 内核配置

准备 `.config`：

```bash
mkdir -p "$BUILD"
cp ~/myOsTest/huawei_mem-master/zb/MGLRU/config-6.17.13-mglru "$BUILD/.config"
```

启用 cache_ext、BPF、BTF，并清空签名 key：

```bash
"$SRC/scripts/config" --file "$BUILD/.config" --set-str LOCALVERSION "-cacheext-v2"
"$SRC/scripts/config" --file "$BUILD/.config" -e CACHE_EXT
"$SRC/scripts/config" --file "$BUILD/.config" -e CACHE_EXT_BPF

"$SRC/scripts/config" --file "$BUILD/.config" -e DEBUG_INFO
"$SRC/scripts/config" --file "$BUILD/.config" -e DEBUG_INFO_BTF
```

### 12.7 手动 reclaim 保护验证

使用已有大文件，例如编译产物 `vmlinux`：

```bash
CE=/sys/kernel/debug/cache_ext
TEST=/home/gaia/myOsTest/linux-hwe-6.17-cacheext-v2-build/vmlinux

read MAJ MIN INO PAGES < <(python3 - <<'PY'
import os
p=os.path.expanduser("~/myOsTest/linux-hwe-6.17-cacheext-v2-build/vmlinux")
st=os.stat(p)
page_size=os.sysconf("SC_PAGE_SIZE")
pages=(st.st_size + page_size - 1) // page_size - 1
print(os.major(st.st_dev), os.minor(st.st_dev), st.st_ino, pages)
PY
)

echo "profile clear" | sudo tee "$CE"
echo "clear" | sudo tee "$CE"
echo "enable 1" | sudo tee "$CE"
echo "app 4" | sudo tee "$CE"
echo "policy builtin" | sudo tee "$CE"
echo "bpf enable 0" | sudo tee "$CE"
echo "profile add 4 22 $MAJ $MIN $INO 0 $PAGES 1" | sudo tee "$CE"
echo "predicted_op 4 22" | sudo tee "$CE"

sudo cat "$CE"
```

成功标准：

```text
cache_ext enabled: 1
app_id: 4
policy_mode: builtin
current_predicted_next_op: 22
profiles:
[0] app=4 op=22 dev=<MAJ>:<MIN> ino=<INO> index=0-<PAGES> priority=1
```

用 cgroup 安全触发 reclaim，避免全局压测把虚拟机卡死：

```bash
CE=/sys/kernel/debug/cache_ext
CG=/sys/fs/cgroup/cacheext_test

sudo mkdir -p "$CG"
echo 900M | sudo tee "$CG/memory.max"
echo 0 | sudo tee "$CG/memory.swap.max" 2>/dev/null || true

sync
echo 3 | sudo tee /proc/sys/vm/drop_caches

sudo bash -c '
echo $$ > /sys/fs/cgroup/cacheext_test/cgroup.procs

dd if=/home/gaia/myOsTest/linux-hwe-6.17-cacheext-v2-build/vmlinux of=/dev/null bs=4M status=progress

python3 - <<PY
import time
chunks = []
try:
    for i in range(700):
        chunks.append(bytearray(1024 * 1024))
        if i % 100 == 0:
            print("allocated", i, "MB")
        time.sleep(0.003)
except MemoryError:
    print("MemoryError")
time.sleep(2)
PY
'

sudo cat "$CE"
```

有效结果示例：

```text
profile_hits: 17711
protected_folios: 17711
skipped_reclaim: 17711
```

含义：

```text
MGLRU reclaim 扫描到 folio
    -> cache_ext_match_folio() 命中 profile
    -> cache_ext_can_isolate() 返回 false
    -> MGLRU 跳过 isolate/reclaim
    -> skipped_reclaim 增加
```

### 12.8 eBPF / Markov 自动预测验证

检查 loader 参数和 CSV：

```bash
cd ~/myOsTest/huawei_mem-master/zb/MGLRU

ls -lh /sys/kernel/btf/vmlinux
python3 ebpf/cache_ext_loader.py --help
head -n 5 generated/cache_ext_markov_transition.csv
head -n 5 generated/cache_ext_page_profile.csv
```

Markov CSV 示例：

```text
app_id,order,ctx0,ctx1,ctx2,ctx3,next_op,count,prob
4,4,2,3,4,5,22,191,0.221065
```

表示 history 为 `2,3,4,5` 时预测 `next_op=22`。

如果 loader 报错：

```text
ERROR: libbpf.a missing
```

编译 libbpf：

```bash
cd ~/myOsTest
SRC=$PWD/linux-hwe-6.17-6.17.0

make -C "$SRC/tools/lib/bpf" -j$(nproc)
ls -lh "$SRC/tools/lib/bpf/libbpf.a"
```

如果系统 `/usr/sbin/bpftool` 生成 0 字节 `vmlinux.h`，改用源码树自带 bpftool：

```bash
cd ~/myOsTest/huawei_mem-master/zb/MGLRU

SRC=~/myOsTest/linux-hwe-6.17-6.17.0
rm -f ebpf/vmlinux.h

make -C "$SRC/tools/bpf/bpftool" -j1 2>&1 | tee ~/myOsTest/build-bpftool.log

BPFT=~/myOsTest/linux-hwe-6.17-6.17.0/tools/bpf/bpftool/bpftool
"$BPFT" btf dump file /sys/kernel/btf/vmlinux format c > ebpf/vmlinux.h

ls -lh ebpf/vmlinux.h
head -n 5 ebpf/vmlinux.h
```

成功结果：

```text
ebpf/vmlinux.h 约数 MB
#ifndef __VMLINUX_H__
#define __VMLINUX_H__
```

如果 BPF 编译报结构体重复定义：

```text
error: redefinition of 'cache_ext_bpf_cycle_ctx'
```

原因通常是 `vmlinux.h` 已包含内核里的 `struct cache_ext_bpf_cycle_ctx`，而 `ebpf/cache_ext_bpf_common.h` 又定义了一遍。修复方向是让公共头在 `__VMLINUX_H__` 已定义时跳过重复结构体定义：

```c
#if !defined(CACHE_EXT_SKIP_CTX) && !defined(__VMLINUX_H__)
struct cache_ext_bpf_ctx {
	...
};
#endif

#ifndef __VMLINUX_H__
struct cache_ext_bpf_cycle_ctx {
	...
};
#endif
```

启动 loader：

```bash
cd ~/myOsTest/huawei_mem-master/zb/MGLRU

read CTX0 CTX1 CTX2 CTX3 NEXTOP < <(awk -F, 'NR==2 {print $3, $4, $5, $6, $7}' generated/cache_ext_markov_transition.csv)
echo "CTX=$CTX0 $CTX1 $CTX2 $CTX3 NEXTOP=$NEXTOP"

sudo pkill -f "cache_ext_loader.py" 2>/dev/null || true

LOG=~/myOsTest/cache_ext_bpf_loader.log
: > "$LOG"

sudo -E python3 ebpf/cache_ext_loader.py \
  --markov-csv generated/cache_ext_markov_transition.csv \
  --profile-csv generated/cache_ext_page_profile.csv \
  --kernel-src ~/myOsTest/linux-hwe-6.17-6.17.0 \
  --kernel-build ~/myOsTest/linux-hwe-6.17-cacheext-v2-build \
  --app-id 4 \
  --limit 1000 \
  --set-history "$CTX0" "$CTX1" "$CTX2" "$CTX3" \
  > "$LOG" 2>&1 &

echo $! > ~/myOsTest/cache_ext_bpf_loader.pid

sudo cat /sys/kernel/debug/cache_ext
```

成功标志：

```text
policy_mode: bpf
bpf_enabled: 1
current_predicted_next_op: 22
```

触发 reclaim 后，BPF 自动预测成功示例：

```text
policy_mode: bpf
bpf_enabled: 1
cycle_seq: 305
current_predicted_next_op: 22
predicted_updates: 307
cycle_refreshes: 305
active_hint_updates: 307
bpf_predict_calls: 305
bpf_predict_hits: 305
bpf_predict_miss: 0
bpf_predict_errors: 0
```

含义：

```text
MGLRU reclaim cycle 触发
    -> cache_ext_begin_reclaim_cycle()
    -> 调用 cache_ext_bpf_predict()
    -> eBPF 查询 Markov map
    -> 命中 history = 2,3,4,5
    -> 预测 next_op = 22
    -> 更新 current_predicted_next_op
```
