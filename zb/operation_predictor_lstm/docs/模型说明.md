# zb 模型说明

本文档说明 `zb/operation_predictor_lstm` 目录下保留的两个下一应用预测模型：

- `app_lstm_next`
- `v3_aligned`

这两个模型都做同一类任务：根据用户最近一段时间内的前台应用切换历史，预测下一次会切换到哪个应用。

## 快速定位

建议所有命令都从 `zb/operation_predictor_lstm` 目录运行：

```bash
cd zb/operation_predictor_lstm
pip install -r requirements.txt
```

核心目录：

- `app_lstm_next/`：主模型，WhatsNextApp 风格双向 LSTM。
- `v3_aligned/`：对齐版 V3 单向 LSTM，对照 `app_lstm_next` 的输入数据。
- `data/vocab/`：共享词表和原始 Excel。
- `data/raw/lsapp/`：从 Excel 生成的 `app_events.csv`。
- `app_lstm_next/data/processed/app_lstm_next/`：`app_lstm_next` 默认训练数据。
- `outputs/checkpoints/`：模型 checkpoint。
- `outputs/results/`：评估结果和逐样本推理 trace。

## 数据来源和处理链路

原始数据文件：

```text
data/vocab/大学生-100-interaction-jank.xlsx
```

第一步，从 Excel 生成前台应用事件表：

```bash
python data/raw/lsapp/generate_app_events.py \
  --input data/vocab/大学生-100-interaction-jank.xlsx \
  --app-vocab data/vocab/app_vocab.json \
  --output data/raw/lsapp/app_events.csv
```

输出：

```text
data/raw/lsapp/app_events.csv
data/raw/lsapp/app_events_check.txt
data/raw/lsapp/event_type_check.txt
data/raw/lsapp/bad_timestamp.log
data/raw/lsapp/invalid_app_vocab_mapping.log
data/raw/lsapp/unknown_event.log
```

`app_events.csv` 的关键字段：

- `user_id`
- `timestamp`
- `foreground_app`
- `opened_apps`
- `user_group`

第二步，生成 `app_lstm_next` 训练样本：

```bash
python -m app_lstm_next.src.data.build_app_lstm_next_dataset \
  --input-file data/raw/lsapp/app_events.csv \
  --output-dir app_lstm_next/data/processed/app_lstm_next \
  --vocab-path app_lstm_next/data/vocab/app_vocab_next.json \
  --input-vocab-path app_lstm_next/data/vocab/input_app_vocab.json \
  --target-vocab-path app_lstm_next/data/vocab/target_app_vocab.json \
  --window-seconds 3600 \
  --history-len 23 \
  --seed 42
```

输出：

```text
app_lstm_next/data/processed/app_lstm_next/train.csv
app_lstm_next/data/processed/app_lstm_next/val.csv
app_lstm_next/data/processed/app_lstm_next/test.csv
app_lstm_next/data/processed/app_lstm_next/dataset_meta.json
app_lstm_next/data/vocab/app_vocab_next.json
app_lstm_next/data/vocab/input_app_vocab.json
app_lstm_next/data/vocab/target_app_vocab.json
```

样本字段：

- `user_id`：只用于切分和校验，不输入模型。
- `target_timestamp`：只用于排序和追踪，不输入模型。
- `history_apps`：模型输入，使用 `|` 分隔的历史前台应用序列。
- `target_app`：预测标签。

当前数据配置：

- 历史窗口：3600 秒
- 最大历史长度：23
- 用户级 train/val/test 切分
- 训练样本数：56163
- 验证样本数：6737
- 测试样本数：7982
- 输入词表大小：22
- 目标应用类别数：19

## 模型一：app_lstm_next

位置：

```text
app_lstm_next/
```

模型代码：

```text
app_lstm_next/models/app_lstm_next.py
```

训练入口：

```text
app_lstm_next/train/train_app_lstm_next.py
train_app_lstm_next.py
```

评估入口：

```text
app_lstm_next/eval/evaluate_app_lstm_next.py
evaluate_app_lstm_next.py
```

推理入口：

```text
app_lstm_next/infer/infer_app_lstm_next.py
```

### 任务定义

输入用户最近一小时内最多 23 个不同前台应用切换历史，预测下一次不同前台应用。

模型实际只使用：

```text
history_apps
```

标签为：

```text
target_app
```

### 模型结构

`app_lstm_next` 是双向 LSTM：

```text
Embedding -> Bidirectional LSTM -> Dropout -> Linear -> next-app logits
```

默认超参数：

- embedding_dim：64
- hidden_dim：64
- dropout：0.2
- epochs：20
- batch_size：8
- learning_rate：1e-3
- top_k：1 到 8
- seed：42

### 训练

```bash
python -m app_lstm_next.train.train_app_lstm_next
```

或使用根级兼容入口：

```bash
python train_app_lstm_next.py
```

带逐样本推理 trace 的训练：

```bash
python -m app_lstm_next.train.train_app_lstm_next \
  --inference-trace-output outputs/results/app_lstm_next/inference_trace.csv \
  --inference-trace-splits train val test \
  --inference-trace-top-k 8
```

默认读取：

```text
app_lstm_next/data/processed/app_lstm_next/
app_lstm_next/data/vocab/input_app_vocab.json
app_lstm_next/data/vocab/target_app_vocab.json
```

默认输出：

```text
outputs/checkpoints/app_lstm_next/app_lstm_next_bidirectional_last.pt
outputs/checkpoints/app_lstm_next/app_lstm_next_bidirectional_best_val_recall8.pt
outputs/results/app_lstm_next/results.csv
```

### 评估

```bash
python -m app_lstm_next.eval.evaluate_app_lstm_next \
  --checkpoint outputs/checkpoints/app_lstm_next/app_lstm_next_bidirectional_best_val_recall8.pt \
  --dataset-dir app_lstm_next/data/processed/app_lstm_next \
  --output outputs/results/app_lstm_next/eval_results.csv
```

或使用根级兼容入口：

```bash
python evaluate_app_lstm_next.py \
  --checkpoint outputs/checkpoints/app_lstm_next/app_lstm_next_bidirectional_best_val_recall8.pt
```

结果指标写入 CSV，核心字段包括：

- `split`
- `checkpoint_type`
- `k`
- `recall_at_k`
- `loss`
- `mrr`
- `num_samples`

### 单样本推理

```bash
python -m app_lstm_next.infer.infer_app_lstm_next \
  --checkpoint outputs/checkpoints/app_lstm_next/app_lstm_next_bidirectional_best_val_recall8.pt \
  --history-apps "微信|浏览器|WPS" \
  --top-k 8 \
  --show-probabilities
```

`--history-apps` 使用 `|` 分隔应用名。应用名应尽量来自：

```text
app_lstm_next/data/vocab/input_app_vocab.json
```

如果历史应用不在输入词表中，会映射到 `<UNKNOWN>`。

## 模型二：v3_aligned

位置：

```text
v3_aligned/
```

模型代码：

```text
v3_aligned/models/app_lstm_aligned.py
```

训练入口：

```text
v3_aligned/scripts/train_next_app.py
```

### 任务定义

`v3_aligned` 是用于和 `app_lstm_next` 做结构对照的 V3 风格下一应用预测模型。

当前训练入口默认直接读取 `app_lstm_next` 的同一套 CSV 切分：

```text
app_lstm_next/data/processed/app_lstm_next/train.csv
app_lstm_next/data/processed/app_lstm_next/val.csv
app_lstm_next/data/processed/app_lstm_next/test.csv
```

这样可以保证两个模型的训练、验证、测试样本一致，便于比较模型结构差异。

模型实际只使用：

```text
history_apps
```

标签为：

```text
target_app
```

`user_id` 和 `target_timestamp` 只用于校验、去重和 trace。

### 模型结构

`v3_aligned` 是单向 LSTM：

```text
Embedding -> LSTM -> Linear/ReLU/Dropout -> next_app_head
```

默认超参数：

- app_embedding_dim：32
- hidden_dim：64
- dropout：0.2
- epochs：20
- batch_size：8
- learning_rate：1e-3
- top_k：1 到 8
- seed：42

### 与 app_lstm_next 的区别

共同点：

- 使用相同的 train/val/test CSV。
- 使用相同的输入应用词表和目标应用词表。
- 预测同一个 `target_app`。
- 默认都评估 Recall@K。

主要区别：

- `app_lstm_next` 使用双向 LSTM。
- `v3_aligned` 使用单向 LSTM。
- `app_lstm_next` 默认 embedding_dim 为 64。
- `v3_aligned` 默认 app_embedding_dim 为 32。
- `v3_aligned` 保留 V3 风格的 `shared Linear/ReLU/Dropout -> next_app_head` 结构。

### 训练

```bash
python -m v3_aligned.scripts.train_next_app
```

带逐样本推理 trace 的训练：

```bash
python -m v3_aligned.scripts.train_next_app \
  --inference-trace-output outputs/results/v3_aligned/inference_trace.csv \
  --inference-trace-splits train val test \
  --inference-trace-top-k 8
```

默认读取：

```text
app_lstm_next/data/processed/app_lstm_next/
app_lstm_next/data/vocab/input_app_vocab.json
app_lstm_next/data/vocab/target_app_vocab.json
```

默认输出：

```text
outputs/checkpoints/v3_aligned/v3_aligned_last.pt
outputs/checkpoints/v3_aligned/v3_aligned_best_val_recall8.pt
outputs/results/v3_aligned/results.csv
```

### 评估方式

`v3_aligned` 的训练脚本会在训练结束后分别加载 last 和 best checkpoint，并在 val/test 上输出结果。当前目录没有单独拆出的 `v3_aligned` 评估脚本，如需重新评估，建议重新运行训练脚本或从 `train_next_app.py` 中复用 `evaluate_next_app` 逻辑。

## V3 对齐数据产物说明

目录中保留了 V3 对齐数据构建脚本：

```text
v3/src/data/build_v3_next_app_aligned_dataset.py
```

可运行：

```bash
python -m v3.src.data.build_v3_next_app_aligned_dataset \
  --raw-file data/raw/lsapp/app_events.csv \
  --next-dataset-dir app_lstm_next/data/processed/app_lstm_next \
  --app-vocab app_lstm_next/data/vocab/app_vocab_next.json \
  --target-app-vocab app_lstm_next/data/vocab/target_app_vocab.json \
  --group-vocab data/vocab/user_group_vocab.json \
  --output-dir data/processed/v3_next_app_aligned \
  --history-len 23 \
  --window-seconds 3600 \
  --seed 42
```

输出：

```text
data/processed/v3_next_app_aligned/train.csv
data/processed/v3_next_app_aligned/val.csv
data/processed/v3_next_app_aligned/test.csv
data/processed/v3_next_app_aligned/alignment_report.csv
data/processed/v3_next_app_aligned/dataset_meta.json
data/processed/v3_next_app_aligned/aligned_train_sample_ids.txt
data/processed/v3_next_app_aligned/aligned_val_sample_ids.txt
data/processed/v3_next_app_aligned/aligned_test_sample_ids.txt
```

注意：当前 `v3_aligned/scripts/train_next_app.py` 默认不读取
`data/processed/v3_next_app_aligned/`，而是读取 `app_lstm_next` 的原始对齐 CSV。
`v3_next_app_aligned` 目录主要用于保留 V3 特征对齐数据和对齐报告。如果要让
`v3_aligned` 训练入口直接消费这套 V3 对齐数据，需要先检查 padded `history_apps`
和当前训练脚本的样本校验逻辑是否匹配。

## 词表说明

`app_lstm_next` 使用自己的模型词表：

```text
app_lstm_next/data/vocab/input_app_vocab.json
app_lstm_next/data/vocab/target_app_vocab.json
app_lstm_next/data/vocab/app_vocab_next.json
```

根级共享词表：

```text
data/vocab/app_vocab.json
data/vocab/user_group_vocab.json
data/vocab/app_vocab_final.json
data/vocab/app_vocab_duration1.json
```

其中：

- `app_vocab.json` 用于从原始 Excel 生成 `app_events.csv`。
- `input_app_vocab.json` 用于模型输入历史应用编码，包含 `<PAD>` 和 `<UNKNOWN>`。
- `target_app_vocab.json` 用于预测标签编码，不应包含 `<PAD>`、`<UNKNOWN>`、`<SOS>`、`<EOS>`。
- `app_vocab_next.json` 是 `app_lstm_next` 的兼容词表，当前等价于输入应用词表。

## 常见注意事项

- 运行训练前，先确认 `torch` 已安装。
- 所有命令建议从 `zb/operation_predictor_lstm` 根目录执行。
- `dataset_meta.json` 中可能保留历史生成时的绝对路径，路径里可能出现 `lzx`；这些主要是记录信息。脚本实际运行时会按当前 `zb/operation_predictor_lstm` 根目录重新解析默认路径。
- 不要把 `data/processed/v3_next_app_aligned/` 直接当成当前 `v3_aligned` 默认训练输入，除非已经同步调整训练脚本的数据校验和字段读取逻辑。
- 如果重新生成数据，建议先备份旧的 `outputs/` 或指定新的输出目录，避免覆盖已有实验结果。
